# KemoShow

![Kemoshow logo](/assets/icon/icon-transparent.png)

A cross-platform slideshow viewer for Kemono-type websites
([pawchive.pw](https://pawchive.pw), [kemono.cr](https://kemono.cr), and
[coomer.su](https://coomer.su)).

Every image and video of a search result or author is flattened into a single,
endless slideshow — no pagination, no clicking through individual posts.

## Features

- **Post search and author search**, with author autocomplete backed by the
  server-wide creator directory (fetched in the background and cached for the
  runtime of the app).
- **Favourites**: star a post search from the search field or an author from the
  result list, then reopen either from the star button in the header. Each
  favourite remembers its server, so opening one switches servers automatically.
  The slideshow header shows the same star toggle for the search or author being
  viewed.
- **Flattened slideshow** of all primary files and attachments of all posts.
- **Infinite scrolling**: the next page of posts is requested when only five
  media items are left.
- **Mobile**: swipe horizontally between media.
- **Desktop**: full keyboard navigation, including video seeking that does not
  interfere with slide navigation. The shortcut reference is only shown on
  desktop builds.
- **Video**: custom controls, a thin always-visible progress bar at the top of
  the screen, mute and seek support.
- **Save media**: download the current image or video. On mobile, choose between
  adding it to the system gallery or saving it to a folder in the system save
  dialog; on desktop the app asks for a destination folder. The header button
  shows download progress.
- **Settings** (gear icon on the search screen), persisted between runs:
  - **Scan post descriptions for media** — adds links in a post's body that
    point directly at an image or video (`.png`, `.jpg`, `.gif`, `.mp4`, `.webm`,
    …) to the slideshow. Attachments are always included. Post search results
    usually omit post bodies, so this mainly affects author slideshows.
  - **Preload ahead (0–10)** — loads upcoming images in the background so
    swiping feels instant. Images are decoded at screen size, so a handful can
    be cached without exhausting memory. `0` disables preloading; videos are
    always opened when they become visible.

## Keyboard shortcuts

| Keys | Action |
| --- | --- |
| `←` / `→`, `A` / `D` | Previous / next media |
| `Space`, `K` | Play or pause the video |
| `↑` / `↓`, `W` / `S` | Seek 5 seconds |
| `J` / `L` | Seek 10 seconds |
| `Shift` + `←` / `→` | Seek 30 seconds |
| `M` | Mute / unmute |
| `Ctrl` / `⌘` + `S` | Save the current media |
| `Home` / `End` | First / last loaded media |
| `H`, `?` | Show the shortcut reference |
| `Esc` | Back to search |

## Releases

Pushing a `v*` tag publishes a GitHub release with an Android APK and a Windows
x64 archive, built by [`.github/workflows/release.yml`](.github/workflows/release.yml):

```sh
git tag v0.1.0
git push origin v0.1.0
```

The workflow first runs `flutter analyze` and `flutter test`, then builds the
binaries and attaches them to the release. It can also be started manually from
the Actions tab with an existing tag name. Flutter `3.47.8` is pinned in the
workflow's `FLUTTER_VERSION` variable, and the APK's `versionCode` is taken from
the workflow run number so every release can be installed over the previous one.

The APK is signed with the project's own release key, provided to the workflow
through repository secrets:

| Secret | Contents |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | Base64 of the `flutter-release.jks` keystore |
| `ANDROID_KEYSTORE_PASSWORD` | Keystore password, also used for the key |
| `ANDROID_KEY_ALIAS` | Optional; read from the keystore when unset |

The keystore and key share one password, so the workflow reuses
`ANDROID_KEYSTORE_PASSWORD` for both.

The workflow decodes the keystore to `android/app/flutter-release.jks`, writes
the git-ignored `android/key.properties`, builds with
`REQUIRE_RELEASE_SIGNING=true` (a missing keystore fails the build instead of
silently producing a debug-signed APK), and deletes both files afterwards.
Releases before this key was introduced were signed with the Flutter debug
keystore: uninstall such a build once before installing a release signed with
the project key.

The Windows archive is portable: unzip it and run `kemoshow.exe` (the Microsoft
Visual C++ 2015–2022 Redistributable may be needed on systems that do not
already have it).

## Development

```sh
flutter pub get
dart run build_runner build   # regenerate dart_mappable mappers
flutter run
flutter test
flutter analyze
```

The JSON models use [dart_mappable](https://pub.dev/packages/dart_mappable);
their `*.mapper.dart` files are generated by `build_runner` and committed.

Platform icons are generated by
[`flutter_launcher_icons`](https://pub.dev/packages/flutter_launcher_icons) from
two sources in `assets/icon/`:

- `icon.png` — the mark on the opaque dark background, used for the legacy
  Android, iOS, macOS and Windows icons.
- `icon-transparent.png` — the mark alone, used both as the Android adaptive
  foreground and as the monochrome layer for Android 13+ themed icons. Android
  tints that layer and only reads its alpha, so no separate white mask is
  needed (an opaque-background mask would instead fill the themed icon).

The generated files are committed; regenerate them after changing either
source:

```sh
dart run flutter_launcher_icons
```

Version `0.14.4` of the generator rewrites every `ASSETCATALOG*` build setting
of the iOS Runner target, so afterwards restore
`ASSETCATALOG_COMPILER_GENERATE_SWIFT_ASSET_SYMBOL_EXTENSIONS = YES;` in
`ios/Runner.xcodeproj/project.pbxproj` (the release workflow does this
automatically).

Release APKs are signed with the keystore configured in `android/key.properties`
(git-ignored, read by [`android/app/build.gradle.kts`](android/app/build.gradle.kts),
relative to `android/app`):

```properties
storeFile=flutter-release.jks
storePassword=...
keyAlias=...
keyPassword=...
# storeType=JKS          # optional; JKS or PKCS12
```

Without that file, `flutter build apk --release` falls back to the debug
keystore so local builds keep working.


## Project layout

```plaintext
lib/
├── core/                  # Server configuration
├── data/
│   ├── models/            # API models (dart_mappable)
│   ├── repositories/      # Caching and pagination
│   └── services/          # API client, settings/favourites storage, downloads
├── domain/
│   ├── models/            # Media, sources, favourites, settings
│   ├── repositories/      # Repository interfaces
│   └── services/          # Media saving interface
└── ui/
    ├── core/              # Shared formatting helpers, platform detection
    └── features/
        ├── favourites/    # Starred post searches/authors (controller + sheet)
        ├── search/        # Search screen (views + view models)
        ├── settings/      # Settings dialog, controller, persistence
        └── slideshow/     # Slideshow screen (views + view models)
```

Settings and favourites are stored with
[`shared_preferences`](https://pub.dev/packages/shared_preferences) behind
small `SettingsStore`/`FavouritesStore` interfaces, so tests can swap in
in-memory stores. Favourites are serialized as a versioned JSON list under
`favourites.v1`; unknown or malformed entries are skipped on load.

The API specification is available in [openapi.json](openapi.json).
